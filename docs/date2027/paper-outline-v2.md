## I. Introduction

**第 1 段：Functional Verification 的重要性**
在基于仿真的硬件功能验证流程中，测试激励的构造质量直接影响验证空间的探索广度与深度。随着现代硬件系统复杂度的不断提升，测试激励往往需要严格遵循特定的数值约束、时序关系、状态条件及协议规范。传统依赖人工构建和维护大量测试激励的方式，带来了巨大的工程开销。因此，如何根据验证需求自动生成有效的测试激励，已成为硬件验证自动化中的一个重要问题。

**第 2 段：现有自动化方法与 LLM**
近年来，LLM 开始被应用于硬件验证，并被用于自动生成测试激励。一类工作 [5] 直接利用 LLM 根据设计或验证需求生成测试激励；另一类工作 [1][2] 利用 LLM 生成 SystemVerilog constraint，通过约束随机机制进一步生成测试激励；还有一些工作 [3][4] 引入 DSL、template 或其他结构化表示，利用 LLM 将验证需求转换为结构化描述，再由验证框架生成测试激励。

**第 3 段：现有方法的局限**
然而，现有方法对复杂验证意图的表达仍然有限。LLM 直接生成测试激励时，验证需求与具体激励实现紧密耦合；生成 SystemVerilog constraint 虽然引入了更高层次的约束表示，但其语义主要围绕变量取值及其约束关系展开, 难以直接、统一地表达更高层次的验证语义；部分基于 DSL 或 template 的方法虽然提供了更高层次的结构化表示，但通常针对特定验证任务或预定义场景设计，其语义对象和关系受到预定义结构的限制，难以统一组合不同类型的验证关系。因此，现有方法仍缺少一种以验证意图为核心、能够统一表达和组合不同类型验证语义，并将其转换为具体测试激励的验证表示。

**第 4 段：核心思想**
为解决上述问题，本文提出一种类型化验证语义（Typed Verification Semantics），通过类型化 DSL 将验证意图表示为结构化、可组合的语义约束。LLM 可以根据测试需求生成相应的 DSL 描述，类型系统负责检查验证对象及其关系的合法性，SMT solver 则负责求解这些语义约束，并生成满足约束的具体测试激励。由此形成 验证意图 → Typed DSL → SMT → Stimulus 的分层生成流程。

**第 5 段：主要贡献**
- **Typed Verification Semantics**：提出一种类型化验证语义 DSL，用于统一表达和组合不同类型的验证对象及其语义关系，并通过类型系统检查语义表示的合法性。
- **Semantic-to-Stimulus Compilation**：构建从 DSL 到 SMT 约束的编译与求解流程，并将求解结果转换为可执行的测试激励。
- **Systematic Evaluation**：在多个硬件验证任务上，将本文方法与 Direct Stimulus、Direct SV Constraint 以及 HAVEN 等方法进行比较，从生成成本、生成正确性、约束求解能力和覆盖率收敛等方面进行系统评估。

## II. Background

### A. 测试激励生成
1. **测试场景与测试激励** — stimulus 驱动 DUT，探索输入场景、提升覆盖率；目标是在满足验证需求的同时有效探索测试空间。
2. **随机与约束随机激励生成** — CRV 用声明式约束描述测试空间 + 求解器生成实例；将测试需求与具体激励值分离。
3. **定向与覆盖率驱动激励生成** — directed testing / coverage-directed generation 根据验证目标或覆盖率状态调整生成，面向未覆盖行为。

### B. 验证意图
1. **从测试场景到验证意图** — 验证需求是一组条件，构成 Verification Intent：验证对象、属性及其关系；关注"验证什么"而非"如何构造输入"。
2. **验证意图中的约束与关系** — 值关系、对象间关系、时序与状态关系；跨对象整体约束。
3. **复杂验证场景中的验证意图组合** — 实际场景同时含多维语义约束，需要支持不同语义关系的组合。

### C. 验证意图与测试激励生成
1. **从验证意图到约束** — 值/对象/时序关系映射为逻辑约束。
2. **从约束到具体测试激励** — 求解器在满足条件的空间中搜索实例并转为激励。
3. **表示层次** — intent（验证什么）→ 约束（遵循什么条件）→ 激励（具体实例），为统一语义表示提供基础。

## III. Typed Verification Semantics Harness

### A. 方法概述
1. **验证生成中的职责分解** — Harness 作为 LLM 表达验证需求与生成测试激励之间的程序化接口；提供带明确语义和类型约束的表示。
2. **类型化语义作为 Harness 的表达形式** — 显式表示验证对象、属性、值关系、对象关系、时序关系；类型系统限定合法组合；语法确定 + 语义明确，支撑后续语义检查与激励生成。
