# RVProbe token 流程优化：零模型验证

本次仅修改 RVProbe 取证、局部修复和提示词。HAVEN prompt/DSL 不变，模型、轮次、每 intent 最多 4 条 sequence、工具子查询预算及原始 LTL 回放验收不变。没有付费模型请求，没有重标历史实验。

## 当前实现

- `batched-evidence-local-repair-v4`：初始请求提供批准的 RTL 文件目录、精确覆盖计数、固定物理环境和基线身份。完整覆盖缺口、RTL 正文仍按需读取，不注入 HAVEN 原生 DSL 或设计答案。
- 新增批量搜索和批量行区间读取，各最多 8 个子请求。合并相邻/重叠区间；返回额度不足时明确保留每项续读偏移。每个子请求各计一次，仍最多 64 个工具操作、24 次模型请求。
- `skill-core-on-demand-references-v3`：核心 LTL 语义/用法由 skill 提供；原 RAG 正文变为按 ID 读取的冻结参考，不默认内联全部示例。源码白名单、原文验证、逐次哈希校验保留。
- `local-source-repair-v1`：失败后的修复请求仅包含原回答、binding、skill、固定物理条件、诊断；只开放框架参考与完整诊断读取，不开放 RTL 搜索和覆盖重新规划。模型仍返回完整 UT，框架不猜测或自动改写语义。
- 编译诊断保留类别、错误码、位置和原始消息，滤除结束计数噪声。初始诊断去重、优先语法错误、最多 8 条，未展示内容可读取完整报告。通用 `Error` 标题下的明确未闭合标识符也能优先反馈，原编译器类别不伪造。
- 保留供应商工具协议要求的完整消息字段；新增请求模式、已用工具预算和历史推理字段字符数统计，不保存推理正文。skill 根据 skill-creator 的单一核心说明原则整理，不收录历史测例答案。

## 验证结果

- 固定 HAVEN Python 环境下 402 项测试：386 通过、16 跳过。
- 新增用例验证初始证据边界、批量合并/Unicode 续读、非法参数/源码变化拒绝、子查询预算、协议字段保留、诊断完整性和两次模型桩回答之间的局部修复切换。
- 真实 Nix/bubblewrap/scalac：正确 UT 通过；未闭合反引号及错误硬件类型 API 均在源码位置报错。没有调用模型或 JG。
- skill frontmatter 验证通过。
