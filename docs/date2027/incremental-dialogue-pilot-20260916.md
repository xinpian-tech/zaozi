# 增量对话试跑与后续评估计划

日期：2026-09-16。此记录不覆盖已有实验结果，不宣称整套后续实验已经完成。

## 已实施

- 新增 `--rvprobe-dialogue-policy incremental`，跨 batch → paired → coverage → generation 全链路显式传递并记录。
- 默认仍保留原 `staged`，用于冻结的历史基线与明确的对照；HAVEN 请求不改。
- 新路径的 skill/spec/IO/初始证据只出现在逻辑对话开头；后续追加真实 assistant tool call 和对应 tool result，不重新打包累计证据。
- 信息足够后直接输出 LTL，不再强制 READY 和独立 authoring 请求。
- DeepSeek 返回的 reasoning_content 仅在同一对话内存中保留并回传同一服务商，以满足推理工具调用协议；不写磁盘、不发送给用户。记录仅含字符数、用量和请求哈希。
- 超过工具条目预算的调用不执行，返回匹配其 ID 的明确拒绝；随后关闭工具，保留最终 LTL 输出机会。不会伪造读取成功或扩大 64 条目预算。
- 请求总数上限仍为 24；最后一次禁用工具。超时、截断仍如实记录，不自动重发可能已计费的请求。
- `report_usage_detail.py` 导出 80 个单元的缓存、推理、非推理、原始阶段时间、失败/修复记录，以及逐轮覆盖率 CSV；不推测费率，不将缺失数据当作零。
