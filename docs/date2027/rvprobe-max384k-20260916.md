# RVProbe 四个失败设计的大生成预算重跑

用户要求尝试更大的 DeepSeek 生成额度，重跑 RVProbe 失败设计。2026-09-16 UTC
启动新批次，不覆盖或替换已有 16×4 正式结果。

## 预先指定的条件

- 设计：ALU、UE_SPI、UE_UART、AXIL_RAM，均从固定 Stage-1 开始独立新跑。
- 模型仍为 `deepseek-v4-flash-vision-exp`；不显式更改 thinking/reasoning_effort。
- 请求明确发送 `max_tokens=393216`，即 384K，含推理与最终回答，不保证保留回答额度。
- RVProbe 每 HTTP 请求时限从 600 秒改为 3600 秒，避免时限先于较大额度耗尽。
- 其他条件保持：固定 Stage-1、raw IO、最多 3 轮、每 intent 最多 4 witness、原求解时限。
- 两设计并发，单项失败保留并继续，完成后校验归档并释放对应 `/dev/shm` 副本。
- HAVEN 的提示词、参数和结果不改；没有启动新的 HAVEN 实验。

这是大预算诊断批次，不是原公平预算下的四方法比较。新的模型输出也是变量，因此不能把
所有覆盖率或状态变化都归因于 max_tokens。ALU、UE_SPI 旧失败为推理耗尽；UE_UART 为
HTTP 响应读取中断；AXIL_RAM 为 Yosys 后端错误。更大预算不保证修复后二者。

## 实际参数与生效判据

`--rvprobe-max-tokens` 和 `--rvprobe-request-timeout` 从批次传到 coverage runner，
仅进入 RVProbe 生成子进程。`--max-tokens` 最终进入每一次模型请求的 JSON。
请求事件记录 `requested_max_tokens`、`request_timeout_seconds`；manifest 保留该配置。
不设置新参数时，原请求 payload 保持原样，不主动加 token 或 effort 限制。

收到正常响应只能说明接口接受此请求，不能证明网关没有静默限制。判断是否突破旧 64K
应检查实际 `completion_tokens`，以及是否仍在 65536 处 `finish_reason=length`。
未知 usage 仍按未知记录；失败和长推理费用不抹除。

## 最终结果

四项均已结束，3 项正常完成、1 项失败，批次墙钟约 35.93 分钟。
新增总用量 930,319 tokens，所有请求 usage 完整，未出现 `finish_reason=length`。
各设计固定 Stage-1、基线 bins、覆盖率分母和费用逐项核验；均已归档并迁出内存盘。

| 设计 | 状态 | 原覆盖率 | 新覆盖率 | 新 tokens | 接受轮次 | 新 Stage-2 秒 |
|---|---|---:|---:|---:|---:|---:|
| ALU | completed | 96.52% | 97.85% | 254,448 | 3 | 1,331.56 |
| UE_SPI | failed | 76.41% | 46.04% | 258,284 | 0 | 202.67 |
| UE_UART | completed | 89.21% | 89.45% | 330,046 | 3 | 1,380.71 |
| AXIL_RAM | completed | 85.80% | 92.94% | 87,541 | 2 | 631.41 |

关键证据：ALU 第二轮单次 `completion_tokens=84037`，其中 `reasoning_tokens=83038`，
`finish_reason=stop`，返回 2,482 字符 LTL，HTTP 耗时 368.77 秒。
该轮通过完整回放，使综合覆盖率由 96.02% 升到 97.57%；第三轮进一步达到 97.85%。
因此至少确认实验接口允许突破旧 64K 上限，且超过旧上限的输出产生了有效激励。
没有任何请求用满 393216，因此不声称已经验证整个 384K 区间的服务行为。

UE_SPI 此次在第一轮遇到 JG `ERROR (EOBS012): Not supported: Liveness cover`；
是另一个失败模式，未接受新增序列，46.04% 是基线覆盖率，不是 LTL 输出截断。
保留该失败，没有修改性质或后端重跑。AXIL_RAM 此次生成了不同性质，未复现旧 Yosys
错误，不代表旧错误已修复。UE_UART 的旧传输中断未复现，也不能归因于 token 上限。

新对照文件位于归档根目录：`budget-comparison.json`、`budget-comparison.csv`、
